## 1. Decisions

| Date | Phase | Decision | Alternatives considered | Why |
|---|---|---|---|---|
| 2026-07-31 | P1.1 | Top-up backfills per (category, repo) cell against that cell's own target, not against an aggregate category gap | Backfill in aggregate and re-apply the global split | Deletions are not uniform: Grafana leaked 34.2% against Prometheus' 19.0%. Aggregate backfill re-applied the 31/35/19/15 split to the gap, which over-filled repos that had not lost rows. Measured drift after two aggregate rounds: FastAPI +10, Grafana -15, Prometheus +10, Pydantic -2 |
| 2026-07-31 | P1.1 | Top-up overshoot is per repo, `1.10 / (1 - measured leak rate)` | One global 1.40 factor | A flat factor under-requests dense repos and over-requests sparse ones. Grafana needs 1.67 against Prometheus' 1.36; at 1.40 a 15-row Grafana gap would have been requested as 21 and netted ~14, landing short a third time |
| 2026-07-31 | P1.1 | Cells above target are trimmed rather than left over-represented | Keep the surplus and accept the drift | A category can hit its total while individual cells sit above and below target, which is still drift off the intended split. Trim is deterministic by question_id and prefers dropping rows without a teacher answer, so no paid work is discarded |
| 2026-07-31 | P1.1 | Teacher regeneration capped at 2 attempts per row, then the row is dropped | Retry until valid | A case class the teacher systematically fails, a comparison the corpus cannot support or an adversarial symbol it keeps answering, never converges. Uncapped, the audit and regenerate loop resubmits it every round and burns budget. The attempt counter lives on `questions`, not `teacher_answers`, so it survives the delete-and-resubmit cycle |
| 2026-07-31 | P1.1 | Teacher prompt forbids supplying the absent side of a one-sided comparison, enforced mechanically | Rely on the prompt alone, or drop one-sided comparisons entirely | The teacher knows all four projects from pretraining and will fill a missing side from memory unless forbidden. `fabricated_absent_side` flags any non-disclaimer sentence naming a project the question asks about but retrieval did not surface. Dropping the rows instead would bias the comparison category toward whatever retrieval happens to cover |
| 2026-07-31 | P1.1 | Statements of absence are exempt from the every-sentence-must-cite rule | Require a citation on every sentence without exception | Caught by a test: an absence statement cites nothing by construction, so the citation rule was rejecting exactly the behaviour the one-sided comparison guard requires. The two rules were in direct conflict |
| 2026-07-31 | P1.1 | Pre-committed k rule, fixed before the retrieval_span numbers existed | Decide k after seeing the measurement | Below 50% comparison multi-repo span, k rises to 8 globally and is re-measured once; at or above, k stays 4 and the fabrication guard carries the load. k is never raised per-category, since training and eval must see identical retrieval. Committing first removes the temptation to rationalise whatever number appears |
| 2026-07-31 | P1.1 | Question sampling is stratified by repo with shares clamped into [15%, 35%] | Sample proportionally to corpus size, equal 25% split per repo | Corpus is 68% Grafana and 6% Pydantic, so proportional sampling would train a Grafana model that has barely seen Pydantic. Water-filling redistributes the capped surplus by corpus size, giving FastAPI 31.1 / Grafana 35.0 / Prometheus 18.9 / Pydantic 15.0. A flat 25% would ignore that FastAPI genuinely has 2.6x Pydantic's documentation |
| 2026-07-31 | P1.1 | Comparison and adversarial calls draw cross-repo pairs 60% of the time, Prometheus paired with Grafana | All cross-repo, or all single-repo | Single-project comparisons (BaseModel vs dataclass) are still worth having, so 60/40 rather than 100%. Prometheus and Grafana alerting is the confusable pair Grafana was chosen for; half those calls draw alerting docs on both sides, and the adversarial prompt asks for a real capability of one project attributed to the other under an invented name |
| 2026-07-31 | P1.1 | Top-up rounds over-request the gap by 25% | Request exactly the shortfall | A top-up is itself subject to dedupe and the adversarial symbol-absence deletion, so requesting the exact gap lands short again. Sampling is offset by 17 x round so a top-up draws different chunks than the round it repairs |
| 2026-07-31 | P1.1 | Grafana `docs/sources` replaces Airflow as the fourth corpus repo | Airflow as planned, Kubernetes website, uv docs, three repos only | Airflow carries 1,678 .rst against 192 .md and its markdown is governance, agent skills, and dev tooling, with exactly one file under `docs/`. Grafana gives 763 markdown files, is already P2 stack, and pairs with Prometheus so comparison and adversarial near-miss questions have genuinely confusable material |
| 2026-07-31 | P1.1 | Teacher is `gpt-5-mini` | gpt-5.6-luna (~$0.65), gpt-5.4-mini (~$2.43), gpt-4.1-mini | Projected ~$0.97 for ~1,880 batch answers leaves ~3 full regenerations inside the $5 ceiling, which matters because citation validation can reject a whole batch. luna released 2026-07-30 with unverified Batch and structured-output support. Judge reserved from `gpt-5.4-mini` or `gpt-4.1` so it never scores its own writing |
| 2026-07-31 | P1.1 | Question generation uses `gpt-4.1-mini`, a different family from the teacher | Reuse gpt-5-mini for both | Same cost at batch rates, and a different model phrases questions differently, so the teacher is not answering its own house style |
| 2026-07-31 | P1.1 | Pricing table is hardcoded with a checked-on date, printed on every priced run | Scrape pricing live at execution time | A live scrape of a docs page is a fragile runtime dependency on HTML structure. Verified against developers.openai.com on 2026-07-31; `PRICING_CHECKED` is echoed by every run and `cost_usd` raises on an unknown model rather than silently costing zero |
| 2026-07-31 | P1.1 | Chunk manifest commits metadata only; chunk text lives in Postgres and the dataset | Commit full chunk text in the manifest | Keeps vendored documentation out of the repo. Source URL on every chunk preserves attribution for the MIT and Apache-2.0 sources |
| 2026-07-31 | P1.1 | Corpus fetch supports `--method tarball` alongside the default shallow clone | git clone only | codeload over HTTPS needs no git binary, which unblocks git-less CI and agent sandboxes that deny git. Default stays `--method git` as specified |
| 2026-07-31 | P1.1 | Teacher dry run hits the sync endpoint, not Batch | Dry run through the Batch API for rate parity | Batch has a 24-hour completion window, so a batched dry run cannot gate the same work block. Same model and prompts means measured tokens project directly onto batch rates at half price |
| 2026-07-31 | P0 | GIT BLOCKs use `git add .` | Enumerating specific files per block | Fewer missed files and less paste friction. `.gitignore` plus the `detect-private-key` and `check-added-large-files` pre-commit hooks are the safety net |

## 2. Problems and fixes

| Date | Phase | Problem | Root cause | Fix |
|---|---|---|---|---|
| 2026-07-31 | P1.1 | Every Prometheus/Grafana cross-repo call came back alerting-focused instead of the intended half | The alerting selector used `i % 100 < 50`, but per-repo call counts are only 20-30, so the modulo window never wrapped and the condition was always true | Changed to `i % 10 < 5`. Alerting calls went 54 of 54 to 30 of 54 |
| 2026-07-31 | P1.1 | FastAPI source URLs had doubled, non-resolving anchors like `#previous-steps-previous-steps` | FastAPI pins heading ids with mkdocs attr_list syntax, `## Title { #the-id }`. Slugifying the whole raw heading appended a slug of the already-present id | `split_heading()` extracts an explicit `{ #id }`, strips it from the visible text, and falls back to the slug. Doubled-anchor count across the corpus went 1,000s to 0 |
| 2026-07-31 | P1.1 | Corpus was 16% changelog noise: dependency bumps, PR links, version announcements | FastAPI `release-notes.md` and Grafana `whatsnew/` parse cleanly as prose but are worthless QA material | Excluded them plus pydantic contributor pages. Chunks 7,325 to 6,178, and FastAPI alone dropped 584 changelog chunks |
| 2026-07-31 | P1.1 | `db init` failed with "cannot insert multiple commands into a prepared statement" | The schema is a multi-statement script and passing `%(dim)s` forced psycopg onto the extended query protocol, which is single-statement only | Format the int constant into the SQL and execute with no bind parameters, which uses the simple query protocol |
| 2026-07-31 | P1.1 | `db init` then failed with `role "evalgate" does not exist` against a healthy container | A native Postgres on the dev machine already owned 127.0.0.1:5432 and shadowed the container's port mapping | Local `.env` sets `POSTGRES_PORT=5433`. Compose default stays 5432; this is per-machine config, which is what `.env` is for |
| 2026-07-31 | P1.1 | Ruff TID252 flagged 25 relative imports across the new package | P0 selected the whole `TID` ruleset, whose default bans parent-relative imports | Dropped `TID` from `select`. Relative imports are the idiomatic way for a package to reference siblings |
| 2026-07-31 | P0 | `uv run pytest` failed collection with "import file mismatch" on 2 of 3 members | Each workspace member has its own `tests/test_smoke.py`. pytest's default prepend import mode derives module names from basenames, so three files collided as `test_smoke` | `--import-mode=importlib` in root `addopts`. Note the ini key is not `importmode`; `--strict-config` correctly rejected that first attempt |
| 2026-07-31 | P0 | `pre-commit run --all-files` reported "no files to check" for yaml, toml, and ruff | pre-commit only sees git-tracked files and the scaffold was not committed yet | Verified with an explicit `--files` list instead. Hooks run normally from the first commit onward |
